# نظام إدارة اللجان والاجتماعات — شركة وادي مكة للتقنية

منصة رقمية موحدة لإدارة دورة حياة اللجان داخل الشركة: من طلب التأسيس، إدارة الأعضاء، جدولة الاجتماعات وعقدها، توثيق المحاضر إلكترونيًا، وحتى إدارة القرارات والمهام والوثائق. يستفيد النظام من تقنيات الذكاء الاصطناعي لدعم أعمال اللجان (تلخيص الاجتماعات، استخراج القرارات والمهام، والبحث الذكي داخل الوثائق).

## حالة المشروع

المشروع في مرحلة **التحليل والتصميم** (المرحلة 1 من منهجية التطوير). لا يوجد كود تطبيقي بعد — هذا الريبو يحتوي حاليًا على الهيكلة الأساسية فقط، تمهيدًا لبدء المراحل بالترتيب المعتمد بعد المراجعة والموافقة على كل مرحلة.

## التقنيات المعتمدة

- **Frontend:** React + Vite
- **Backend:** Python
- **Database:** PostgreSQL
- **Authentication:** JWT + bcrypt
- **Authorization:** RBAC
- **Session Tracking:** Redis (لتتبع الجلسات النشطة وإبطال التوكن عند تسجيل الخروج)

## المراجع المعتمدة

كل تطوير على هذا المشروع يلتزم حرفيًا بالوثائق التالية (مصدر الحقيقة الوحيد للمتطلبات والقواعد):

- `SRS` — وثيقة متطلبات النظام (Software Requirements Specification)
- `BRS` — وثيقة متطلبات الأعمال (Business Requirements Specification)
- `CLAUDE.md` — قوانين وتعليمات التطوير (منهجية العمل، الأمان، الـ RBAC، معايير الكود)
- دليل الهوية البصرية وواجهة المستخدم (الألوان، الخطوط، الـ Design Tokens)

## منهجية العمل

يُطوَّر النظام على شكل مراحل (Feature-Based Phases) بالترتيب:

1. التحليل والتصميم
2. إدارة المستخدمين والإدارات
3. إدارة اللجان
4. إدارة الاجتماعات
5. إدارة المهام والقرارات
6. إدارة الوثائق والبحث الذكي
7. الذكاء الاصطناعي والتكاملات الخارجية
8. لوحة التحكم والتقارير
9. الاختبار والأمان
10. النشر والتوثيق

لا تبدأ أي مرحلة جديدة قبل مراجعة المرحلة الحالية واعتمادها صراحةً. لكل Feature يكون الترتيب الداخلي: Requirements & Business Rules → Database → Backend → Frontend → Integration → Testing → Review.

## Git Workflow

- يستخدم الفريق Feature Branches — لا يُرفع أي تغيير تجريبي مباشرة على `main`.
- قبل أي دمج: تشغيل الاختبارات، مراجعة الكود والـ Migrations وتغييرات الـ API والأمان، ثم فتح Pull Request ومراجعته قبل الدمج.

## متغيرات البيئة

راجع ملف `.env.example` لقائمة متغيرات البيئة المطلوبة. لا تُوضع أي قيمة فعلية لأي متغير بيئة داخل الكود أو داخل Git.
