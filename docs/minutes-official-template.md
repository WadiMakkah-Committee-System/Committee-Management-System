# قالب المحضر المعتمد — تصميم البيانات

> المرحلة: المتطلبات + قاعدة البيانات (بانتظار مراجعة صاحب المشروع).
> المواصفات الكاملة المعتمدة: مستند المشروع `minutes_template_spec.md` (Claude Project "ادارة اللجان").
> المرجع: محضر مجلس إدارة شركة وادي مكة للتقنية السادس لعام 2024م.

## 1. الفكرة
قالب رابع يُضاف لقوالب المحاضر الثابتة الحالية (`MINUTES_TEMPLATES` في
`backend/app/services/meeting_minutes_service.py`). عند اختياره بعد انتهاء
الاجتماع، يبني الخادم أقسام المحضر من بيانات الاجتماع، وكل الأقسام تبقى
قابلة للتعديل إلى أن يُرسل المحضر للتوقيع.

## 2. ما هو موجود ويُعاد استخدامه
| الحاجة | الموجود |
|---|---|
| حفظ المحتوى | `meeting_minutes.sections` (JSONB حر) — 0029 |
| المكان ونوع الاجتماع | `meetings.mode` (`remote` / `in_person`) و`meetings.location` — 0020 |
| وقت البداية والانتهاء | `meetings.scheduled_at` و`meetings.ended_at` (احتياطًا `scheduled_end_at`) |
| بنود جدول الأعمال | `meeting_agenda_items` (`title`, `sort_order`) — 0018 |
| حاضر / غائب (عن بعد) | `meeting_attendance` (جلسات دخول تلقائية) — 0043 |
| الضيوف الخارجيون | `meeting_guest_requests` + `users.is_guest` (الاسم من شاشة الدخول) — 0047 |
| الصفة داخل اللجنة | أدوار اللجان: رئيس اللجنة / عضو اللجنة / أمين سر اللجنة — 0016، 0041 |
| الموقّعون | `meeting_minutes_signatures` تُنشأ لكل أعضاء اللجنة عند الإرسال للتوقيع — 0029 |
| رسم التوقيع | `react-signature-canvas` (موجودة بالواجهة) |
| تصدير PDF | `backend/app/services/minutes_pdf_service.py` (reportlab) |

## 3. التغيير على قاعدة البيانات
ملف واحد فقط: `db/migrations/0049_user_saved_signatures.sql`

| الجدول | العمود | النوع | القيود |
|---|---|---|---|
| `user_saved_signatures` | `user_id` | UUID | PK، FK → `users` (حذف متسلسل) |
| | `signature_image` | TEXT | NOT NULL، يبدأ بـ`data:image/png;base64,`، الطول 30–300,000 |
| | `created_at` / `updated_at` | TIMESTAMPTZ | NOT NULL، `updated_at` يتحدث بـtrigger |

- جدول مستقل لا عمود في `users`: صفوف `users` تُحمَّل تلقائيًا في أغلب
  المسارات، وصورة التوقيع كبيرة.
- RLS مفعّل بنفس نمط 0047.
- إضافة فقط: لا يُعدّل أي جدول موجود، وآمن للتطبيق قبل نشر الكود.

**لماذا لا يوجد تغيير آخر؟** محتوى القالب (الترويسة، الجداول، المواضيع،
أرقام القرارات، رقم الاجتماع) يُحفظ داخل `sections` (JSONB) كأقسام مُهيكلة،
لأن كل شيء فيه قابل للتعديل ويخص هذا المحضر وحده. رقم الاجتماع يُحسب لحظة
توليد القالب ولا يُخزَّن على الاجتماع، فتعديله في محضر لا يغيّر ترقيم
الاجتماعات الأخرى.

## 4. هيكل الأقسام داخل `sections` (يُفرض بالخادم في مرحلة الباك إند)
كل قسم: `{ id, kind, order, title, data }`. الأقسام القديمة بدون `kind`
تُعامل كنص (`text`) كما هي الآن — لا يتأثر أي محضر قديم.

| `kind` | المحتوى في `data` | التعبئة |
|---|---|---|
| `header` | `date_text`، `place_text`، `time_text`، `subject_text` | تلقائي |
| `title` | `line1` ("محضر اجتماع")، `line2`، `meeting_number`، `meeting_year` | تلقائي |
| `rich` | `content` (مستند المحرر)، `placeholder` — للفقرة الافتتاحية، فقرة الافتتاح، مناقشة أعضاء اللجنة | يدوي |
| `members_table` | `rows`: `user_id`، `name`، `role_label`، `mode_label`، `status_label` (الرئيس أولًا) | تلقائي |
| `guests_table` | `rows`: `name`، `mode_label`، `role_label` | الاسم تلقائي، الصفة يدوي |
| `agenda_table` | `rows`: `ordinal_label` ("الموضوع الأول")، `title` | تلقائي |
| `topic` | `ordinal_label`، `heading`، `agenda_item_id`، `background` (مستند المحرر)، `decision_number`، `decision` (مستند المحرر) | العناوين تلقائي |
| `closing` | `text` (مع وقت الانتهاء)، `sign_off` ("وعلى ذلك جرى التوقيع،") | تلقائي |
| `signatures` | `heading`، `labels`: `user_id`، `name`، `role_label` | تلقائي (الصور من جدول التوقيعات فقط) |

## 5. قواعد التوليد
- **التاريخ:** `{اليوم} {هجري أم القرى}هـ الموافق {ميلادي}م` بتوقيت الرياض.
- **المكان:** `remote` ← "عبر الاتصال المرئي"، `in_person` ← `meetings.location`.
- **رقم الاجتماع:** 1 + عدد اجتماعات نفس اللجنة غير المحذوفة، المنعقدة في نفس السنة الميلادية، وموعدها قبل هذا الاجتماع.
- **رقم القرار:** `({رقم الموضوع}-{رقم الاجتماع}-{السنة})`.
- **جدول الأعضاء:**
  - **عن بعد:** العضو اللي له جلسة في `meeting_attendance` ← حاضر / عن بعد. واللي ما له جلسة ← غائب / غائب.
  - **حضوري:** ينتظر قرار صاحب المشروع (القسم 7).
- **الضيوف:** الضيوف المقبولون فقط. يختفي الجدول عند العرض وفي PDF إذا كان فارغًا.
- **التوقيعات:** كل أعضاء اللجنة (الرئيس آخر خانة بعرض كامل)، والضيوف لا يوقّعون. صورة التوقيع وتاريخه من `meeting_minutes_signatures` فقط.

## 6. حزم جديدة ستُطلب موافقتها في مراحلها
- **الباك إند:** مكتبة تحويل التاريخ للهجري (أم القرى)، لعدم وجود دعم لها حاليًا.
- **الفرونت إند:** محرر نصوص غني (جداول، ترقيم، نقاط)، لأن المحاضر حاليًا `textarea`.
